### A subcontractor can see what a GC's subcontract commits them to — and how it differs from their bid — before they sign, and push back (Diego)

`claude/awesome-bell-s4g7b9`

Phase 1 of the AI subcontract review. On any contract version of a job, **Review before signing** reads the agreement and any exhibits (scope, insurance, general conditions) and lists the clauses that put money, risk or a deadline on the sub — pay-if-paid, liquidated damages, indemnity, notice windows, retainage, insurance asks — each with a severity word, the contract's own words, and the page they are on. The person accepts, negotiates, annotates, edits or dismisses each one; nothing is saved to the job and nothing is sent.

Why it is built the way it is:

- **The model reads TEXT that code extracted, not the PDF.** That is the only way to enforce the rule that a finding without a citation is never shown: every quote is checked verbatim against the same text (`lib/specs/quoteMatch.ts`, unchanged, now running at runtime for the first time), the page is located by code rather than taken from the model, a section reference is kept only if it is printed there, and a figure is kept only if its digits are in the quote. Dropped findings are counted on screen. Scanned pages have no text, so they are listed as unread and cost nothing.
- **One chunk per request, driven by the open page**, because a 100-page contract does not fit in a 60-second function — plan ingestion's shape on this feature's own rows, with a lease so two tabs cannot pay twice.
- **Decisions are keyed on the job and the clause, never the run**, so they survive a re-run and carry to the next contract version wherever the wording is unchanged; a later version shows what is new, changed and gone.
- **Its own switch (`SUBCONTRACT_REVIEW`) and its own monthly unit** (`contractPagesUsed`, 600 pages), so one contract package cannot spend a month of quote and COI reading. Each readable page is charged once even though chunks overlap by a page.

**Phase 2, same PR — what it commits you to against what you bid.** The review now compares the contract with the job's own side of the deal: the contract sum against the won bid's base plus ACCEPTED alternates (undecided ones named, allowances never added), retainage against the job's rate and the GC's usual one, the addenda the contract incorporates against those logged and acknowledged on the bid, and contract passages that put on you work your proposal excluded. Exclusions the contract never carries are listed once the whole contract has been read — the one kind of finding that cannot quote the contract, so it quotes YOUR clause and says how many pages were searched. Every number is compared by code; the model only finds the passages, and a clause ref it was not given is dropped. A one-page summary — top risks, money terms, deadlines, insurance asks, scope gaps, questions for the GC — prints from `/jobs/[id]/subcontract-review/[reviewId]/summary`, built by code from the findings and decisions with no second model call.

**Phase 3, same PR — acting on it.** A rider is drafted by code from the job's exclusions and clarifications and every finding marked Negotiating (in the person's own edited words), edited freely, previewed for print, and attached as the job's next contract version — a PDF written server-side, numbered by the version counter, landing where e-sign and DocuSign already are. Attaching sends nothing. Notice windows and deadlines a person confirms from a finding join the alerts as `SUBCONTRACT_OBLIGATION`: a notice window is a rule rather than a date, so it is a STANDING reminder on the job, while a billing cutoff or an entered date goes DUE_SOON and OVERDUE. Insurance asks a person confirms are stored as a clean checklist for the COI work; nothing reads it yet, deliberately. The alerts change is one new kind and one fetch block in the shared alerts files, announced in #prova-build first.

Four migrations, all additive: `20261017180000_add_subcontract_review_ai_feature` (enum member + three integer columns with defaults) `20261017180100_add_subcontract_review` (four tables, every foreign key CASCADE, so the cleanup scripts gain no RESTRICT child of `Job`), `20261017200000_add_subcontract_scope_checks` (one table, the clause it compared against snapshotted), and `20261017220000_add_subcontract_review_actions` (rider, obligation and insurance tables; the rider's link to its contract version is SET NULL so deleting the version keeps the text).

The paid eval (`pnpm eval:subcontract-review` — 100% citation validity, no HIGH finding on a sub-friendly control, planted-clause recall) is written and has NOT been run: the container that wrote it had no API key. Design: `docs/ai/SUBCONTRACT-REVIEW.md`.
