### METHOD v2, doors and windows: the opening training rows are built on the product's own inputs (parity 0 on the 6 door sets)

- **The door model's rows had #1169's bug.** `zzOpeningFeatureTable` detected walls with `detectForSheet` bare (no template, types or vocabulary) and found doors against the finder's raw walls, while the product (`rooms.ts`) finds doors and windows against the runs the stage STORED, on the page's strokes. Every door feature that reads its wall — onWall, thickness, exterior, the wall-lines band, the marked share — came from a different wall set, so door-model.json's LOSO 97.4% described rows the product does not produce (marked PROVISIONAL by the fourth).
- **Now one way:** `productSheetRuns` (the viewer's set-asides over `productDetection`, moved out of `detectWallsForCalibration`), `openingInputs` (stored runs + page strokes, used by `rooms.ts` at all three call sites) and `productDoorRows` (every door, its arcs, marks, kept set and `DOOR_FEATURE_NAMES` row, from the same marks `doorsAndWindowsForSheet` reads — `doorMarkTexts`, shared). The table eval builds both halves on them, keeps the window half with `OFT_SCHEDULE_CACHE`, and the table format; `loso.py` is unchanged.
- **Parity, checked per sheet:** the table run fails a set whose kept doors differ from the product's; on Baker, Bunkie, E Street, Joplin, Green Bay and Topeka **0 differ**. Table: 208 door rows (195 real), 177 window rows (169 real). `productOpenings.test.ts` pins the wiring in CI (either side reverted → red). Product behaviour unchanged (code moved).
- Each row also carries `page` and `at` (hinge and strike for a door, the point for a window, page-width units), so a confident false opening is opened on its sheet without a rerun (the original's ask, for Topeka p74's three false doors).
- `loso.py` (the fourth's patch, carried here): with `LOSO_LABELS=<snapshot>` a sheet whose key is unfinished (`reviewComplete` false) is left out and named — Topeka p74/75/76, Crosslines, MHK and Grand Junction are AI quick passes never finished, and an unfinished key cannot set a line.
- **Re-measured on these rows (the fourth, finished keys only, Joplin's 3 key gaps relabelled):** the every-set-≥97% line is 0.9843 — 86 posts, 0 false, 50 of them unmarked. Provisional: certified only on the Round 22b rebuild.
- **`arcGrey` (grey-pen share of the door's own strokes) was added and taken back out** by rule 5: it moved that line to 0.9974 with 74 posts (12 safe posts fewer) and helped no finished set; dropping it reproduces v1 exactly, which also confirms the table's parity. Kept in git history; the relative form (door grey minus sheet grey) is a candidate for the 22b rebuild.
