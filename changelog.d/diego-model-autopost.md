### METHOD v2, parts 2–3: a learned decision posts itself only past its own measured bar; types and doors plug into the same rows

- **Walls the model is sure of are counted without review**: a run whose stored score is at or above the wall model's `autoPostAt` posts as **"Walls (auto, high confidence)"** — real, counted, out of the junk review, still untyped unless a type source posted it (so the queue still asks its type). **Undo per sheet** (`undoAutoPost`) takes them back to "wall, untyped". Below the bar, unchanged: untyped, in review.
- **Nothing posts today.** `MODEL_EVIDENCE` (in `autoPost.ts`, beside every other source's evidence) is one row per learned decision — walls, types, doors — and each is empty until the second measures it: LOSO pooled precision ≥97% at the chosen score (chosen on LOSO, never held-out) AND the held-out final ≥95%, run once, with the model file named. Behind the company's existing "Auto-post proven items" switch (`autoPostOn`, off by default); turning it on for new companies waits for the final exam.
- **One model reader for every decision** (`readDecisionModel`): `TAKEOFF_WALL_MODEL` / `TAKEOFF_TYPE_MODEL` / `TAKEOFF_DOOR_MODEL`, the same `gbdt-binary-v1` contract (columns equal to the build's, in order, else refused and logged once); the wall reader now goes through it.
- **Review order is NOT changed to "lowest confidence first"**: that order ("by doubt alone") was measured as the slowest of three (26 runs per sheet against 5 for the shipped "likely junk feet" = length × (1 − score)), see `wallReview.ts`. One line (`ReviewOrderBy: "doubt"`) if Diego wants it anyway.
- Tests that fail without each part: `modelAutoPost.test.ts` (bar ignored → red; review keeps auto walls → red; column contract off → red) and `autoPost.dbtest.ts` (no high-confidence label → red; Undo misses them → red; company switch ignored → red).
