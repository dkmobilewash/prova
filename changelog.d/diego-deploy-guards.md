### A failed production deploy is impossible to miss, and impossible to cause by cache

Production deploys were frozen at #1178 for ~12 hours while CI stayed green: every function traced ~5 GB and died at Vercel's limit. The root cause, named by bytes from the `.nft.json` lists: webpack's build-cache packs (`.next/cache/webpack/*-production/*.pack`, up to 980 MB each) were swept into every function's trace whenever Vercel's restored build cache put them on disk — size depended on cache state, not code, which is why one build passed at 46 MB/function beside failures at 5.13 GB. Fixed at the root with `outputFileTracingExcludes` (`.next/cache`, `.next-chrome`): measured 5.17 GB → 0.12 GB per entry on the same build machine. Three guards so a recurrence cannot hide: `function-size-budget.mjs` in CI fails a PR at 4.5 GB per traced entry (warns at 4; fails loudly if it scans nothing), the `vercel-deploy-watch` workflow turns any failed Production deployment into a red check on main plus a `deploy-outage` issue, and the pilot dashboard shows the newest production deployment's state (renders only when `VERCEL_TOKEN` is set).
