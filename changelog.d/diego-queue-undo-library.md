### The queue's Undo takes back the library type its accept added; the counts follow; the panel lists every group

Chrome's queue test on Baker. Accepting a group whose code only the set's legend
defines (C8B) added the type to the company's library and a "C8B walls" item to
the job; Undo put the walls back and left both. Undo now also removes a job item
its accept made and left empty, and a library type its accept added when no run
and no item on any job uses it — checked on the server, since the undo is a
claim from the browser: the user may add types, accepted that legend read on this
job themselves, and the code is one it defines. The legend read is offered again
if the accept was what marked it accepted.

After the undos, "Prices 2 of 12" stayed until a reload: the price items the
accept brought left the queue and were counted as done, and an in-place Undo
never refreshed the page. An Undo now forgets what its accept brought, and the
workspace refreshes after an in-place Undo or Redo.

The panel opened on twelve groups and kept the rest behind "Show the other";
the queue walks all of them (12 against 20 on Baker). The panel lists every
group; past eighteen it says the marks repeat.
