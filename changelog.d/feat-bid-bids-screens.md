### C Stream Bid's `/bid/bids` is now the real bid log, not a due-soon stub
`feat/bid-bids-screens`

`/bid/bids` was a "Due soon" list, a read-only "Outcomes by project" section and a "coming soon" card. It is now the CRM's own bid log rendered inside Bid, so a sub who lives in Bid can do the whole of step one without ever opening the CRM: **log a bid** (paste an invite and let it fill the form, the same-job warning, "Same job as…", "We reached out"), see every invitation **grouped under its project** with status, price and outcome, **edit the bid** (due time, job walk, RFI cutoff), open the **Project** panel (merge, split, **Start the estimate**, prime award), set **each GC's price** off the one estimate and open **each GC's Proposal**, and use the lines, addenda, quotes and job link behind each row.

It is one component, not a fork. The page body moved out of `app/(app)/bids/page.tsx` into `components/BidLog.tsx`, which both products render; the CRM page keeps only what is the CRM's alone (the gate, `PageHeader`, the first-run `EmptyState`) and calls the log with the default surface, so its rendering is unchanged — `app/(app)/bids/page.test.ts` passes untouched. `LogBidForm` and `BidProjectPanel` gained an optional `surface` (default CRM).

Every link on the Bid surface stays inside `/bid`: "Start the estimate" lands on `/bid/estimates/<id>` (it opens on the takeoff) instead of the CRM's `/jobs/new/<id>/items` stepper, the estimate link is `/bid/estimates/<id>`, each GC's Proposal is `/bid/estimates/<id>/proposal?invitation=…`, a missing GC is added in Bid's settings, the "see all"/"Show them all"/due-soon links point at `/bid/bids`, and a due-soon row opens that bid's row in the full list. Bid has no GC page, no per-bid research page and no regret letter, so on Bid the GC and bid names are plain text and there is no regret link rather than a link into the CRM.

How "Start the estimate" knows where to go: the Bid form binds the word `"bid"` and `lib/bid/jobStartDestination.ts` (`estimateStartDestination`) turns it into the path from the job just made — a fixed list of words, never a URL, same rule as `createJob`.

Not done, deliberately: the bid's own page (`/ai/bids/<id>` research, estimate check, decision) and the regret letter are not ported — their names are text on Bid. Other actions the log calls still `revalidatePath("/bids")` only (a Server Action response re-renders the page regardless, so Bid refreshes; the project actions also revalidate `/bid/bids`). No migration; no schema change.

The specific check: `bidLinkCensus.test.ts` now follows the log's imports and still finds no CRM literal; it names the new dynamic sinks with reasons, classifies every value `bidLogHrefs("bid")` and `estimateStartDestination` return, and fails if `BidLog` stops forwarding `surface` to `LogBidForm` or `BidProjectPanel` (mutation-tested: dropping the prop turns it red). `app/bid/(signed-in)/bids/page.test.ts` renders the real Bid page over a two-GC project and requires every anchor to start with `/bid`, on five different views. `e2e/specs/bid-bids.spec.ts` walks log a bid → see it → open its project → Start the estimate → land in `/bid/estimates` (unexecuted: it needs Clerk; the PR's `e2e` job is its first run).

**Found by CI on its first run: the bid log scrolled sideways on a phone.** The per-GC price table (five columns, from `feat/per-gc-bids`) cannot shrink below its content, so at 375px it pushed `/bid/bids` to 402-419px wide (`bid-bids.spec.ts` step 5). The CRM's `/bids` has the same table and hid it, because the CRM's `<main>` scrolls on its own, which is also why no CRM spec caught it. It is now a list where each GC is one row that wraps. Measured in Chromium against the compiled app CSS at 375px: 402px before, 375px after, nothing past the edge.
