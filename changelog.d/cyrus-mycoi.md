### myCOI comes in as a file, because it has no public API (Cyrus)
`cyrus/mycoi`

The myCOI card on Settings → Integrations used to say "Coming soon". It now
opens an import of a myCOI export: paste it or choose the CSV, see which
certificates will be added, which are already here and which rows have a
problem, then press Confirm. Each vendor's line of cover (GL, auto, workers'
comp…) becomes an ordinary certificate-of-insurance row on /compliance, with
its expiry date. From there it reaches the renewal alerts and the bell by the
path every COI already takes. /vendors now shows each vendor's insurance
standing beside its name, to anyone with the compliance permission.

**Why not the API.** myCOI is now illumend (mycoitracking.com 301s to
illumend.ai). Its integrations page says a REST API exists, but it publishes
no developer docs, no auth guide and no self-serve key.
`api.illumend.ai/openapi.json` is reachable, but it's their own backend's
autogenerated spec ("Customer Manager API" 0.1.0). It has no security scheme,
and it includes cron, backoffice and impersonate routes. That isn't a
contract. The card therefore says, in words, that a live connection needs an
API agreement with illumend. `lib/mycoi/api.ts` is a labelled stub that
refuses without touching the network, and no environment variable exists for
it. A variable that nothing reads is the `ALLOW_PREVIEW_MIGRATIONS` shape.

**One migration, additive:** `ComplianceDocument.coverageType` (nullable
text). It is needed because a renewal should only replace the row for the
*same* line of cover. "Newest row for this vendor wins" would let a December
auto renewal hide an October GL lapse. Which row governs is derived per read
in `lib/coi-standing.ts`, and nothing stores "expired". Rows with no coverage
line (every COI before this) are never superseded, so existing alerts are
unchanged.

The check: `lib/actions/mycoi.test.ts`, `lib/coi-standing.test.ts`,
`lib/renewals-coi.test.ts`, `lib/mycoi/*.test.ts`,
`components/MyCoiImport.test.ts`, and the MYCOI block in
`lib/integrations/registry.test.ts`. Twelve mutations were requested and
twelve verdicts returned, all red: owner guard, tenant scope, dedupe,
supersession (three ways), preview-writes, card-planned, stub-network, page
scope, stored expiry, and the missing anchor.

What is NOT known: the exact column headers of a real myCOI export. Nobody
here has one. Columns are matched by ordinary insurance words, and the preview
names every column it didn't use.
