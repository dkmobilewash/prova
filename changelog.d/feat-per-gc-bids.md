### One estimate, a price for each GC: per-GC adjustments, a proposal opened for one GC, and /bids grouped by project (Cyrus)
`feat/per-gc-bids`

A sub bids one job to several GCs from one estimate, often at different prices. `feat/bid-project` gave the job one project and one estimate under any number of invitations, and left the three things below as its not-done list. They are done.

**Heads-up for Slack before the push: this adds a migration** (`20261026090000_bid_gc_price`). It is additive only: three nullable columns on `BidInvitation` (`priceAdjustAmount`, `priceAdjustPercent`, `priceAdjustReason`), no backfill, nothing dropped or tightened. Every existing row reads as "quoted the estimate total as it stands". Generated with `prisma migrate diff --from-schema-datamodel … --to-schema-datamodel …` (no database, no shadow database).

- **A price for each GC.** On any bid on `/bids`, open "Project" and set "Price to <GC>": a dollar amount or a percent off the one estimate (minus takes money off) and a short reason, or "no adjustment" to clear it. The project line shows the estimate total beside every GC's resulting price, the adjustment and reason, and what was actually sent (a different, entered fact). The price is never stored: `lib/estimating/gc-price.ts` works it out from the estimate's live total and the invitation's adjustment every time, in integer cents (a percent is held in thousandths, halves round away from zero), so editing a line on the estimate moves every GC's price with it. An adjustment that would leave a price of zero or below is refused in words, and one that goes bad later (the estimate shrank under a fixed deduct) shows "check adjustment" instead of a number.
- **A proposal for one GC.** `/jobs/<id>/proposal?invitation=<id>` (and the same under `/bid/estimates/<id>/proposal`) is addressed to that GC by the name on its invitation, titled with the project name that GC wrote, priced at that GC's price in all three modes, and sends the bid package to that invitation. By scope splits the GC's price across scopes in proportion, to the cent, by the same largest-remainder rule; Itemized keeps the estimate's lines and adds one "Price adjustment" row so the table still adds up to the total. The reason never prints: it sits in a print-hidden note above the letter. An invitation that is not on this estimate's project is a 404, never the generic letter. With no `?invitation=` the document is what it was; the only addition is a print-hidden "Proposal for" switcher when the project has more than one GC.
- **Outcomes on the project.** `/bids` groups GCs on the same project under one heading (name, bid date, estimate total, and each GC's status and price), with each GC's full row beneath it. A project with a single invitation stays a single row. The heading reads "Didn't get the job" for a GC the prime went elsewhere on, never "Lost". C Stream Bid's `/bid/bids` gets an "Outcomes by project" section from the same component (read-only, no links). That list is still the foundation's stub, so the grouped rows with their edit surfaces are not ported there.

One fix on the way past: the estimate total beside a bid's project line summed soft-deleted lines too, so it could disagree with the proposal and the job header. It reads live lines only now, through `bidTotalOf`.

Not done: `bidAmount` ("price sent") is still typed by hand. Nothing fills it from the GC's price, because a sent price is a fact somebody entered and the two can honestly differ; the project line shows both.

The specific check: `lib/estimating/gc-price.test.ts` (the arithmetic and the form parsing), `proposal-gc-price.test.ts` (lump, scope and itemized add up to the GC's price over hundreds of random prices), `app/(app)/jobs/[id]/proposal/page.test.ts` (the real page rendered: addressee, price, mode links, the 404, the lookup's `where`), and `pnpm exec vitest run --config vitest.db.config.mts lib/estimating/bid-project.dbtest.ts` (two GCs priced differently off one estimate, an edited line moving both, the capability and company refusals, and the proposal's lookup finding only this estimate's GCs). `e2e/specs/bid-desk.spec.ts` step 7b walks it in a browser and has not been run.
